# svgscene-bench — 矢量视图渲染开销基准(离屏)

给应用的矢量(SVG)预览视图做的渲染开销基准,对应 `docs/ROADMAP.md` F3.9 / F3.10 与
`docs/bugfix-triage.md` C.3.1。用来回答"形状累积到几百/几千时,这个视图每帧/每次交互要花多少
时间、占多少内存",以及验证候选实现之间的画面等价性。

不依赖 GUI 交互:用 `QGraphicsScene` + `QGraphicsView` 离屏渲染,形状与 SVG 片段走真实的
`geometrize::exporter`(`getSingleShapeSVGData` / `exportSVGDocument`)。

## 四种被测实现(F3.9 的历史对比口径)

| 名称 | 说明 |
|---|---|
| 旧 | 每批新形状一个全画布 `SvgItem`(上游与应用修复前的实现) |
| 单 item | 全部形状累积在一个 item(片段 append-only + 整体替换渲染器) |
| 分块 | 当前块累积刷新、块满封板不再重解析(**应用采用的实现**) |
| 单件多渲染 | 一个自绘 item + 多个分块渲染器(实测画面差异大,已否决,见 ROADMAP F3.9) |

每种实现各测两个口径:**刷新帧**(本批内容变更 + 该帧渲染)、**稳态帧**(内容未变仅重绘)。

## 交互口径(F3.10 新增)

上面两个口径都在**固定变换**下测,漏掉了用户真正觉得卡的路径。第二十批追加三种交互 tick
(画布 1024×768 = 应用默认处理分辨率,视口 900×600,形状数 1000/2000/5000):

- **缩放 tick**:置到目标倍率并预热后,连续 `view.scale(1.05)` + `render()` 计时取中位;
  倍率扫 {1,2,4,6,8,16}——4096 门槛在 1024 画布上 4x 即触顶,故 6x/8x/16x 覆盖"门槛之上"。
- **拖动 tick**:`horizontalScrollBar()->setValue(+8)` + `render()` 计时,测 2x(门槛下)与 6x(门槛上)。
- **生成帧**:追加一批形状(重拼文档 + 换渲染器)后 `render()` 计时,测 1x 与 6x。
- **手势起点**:进入交互期(切 item 坐标缓存)并触发首次重建的一次性代价。

同一进程内按配置重建场景做**同会话受控 A/B**(跨轮比会被机器负载噪声污染,见 ROADMAP 陷阱 #28),
表格里每种形状数会并排打印多个配置(现状 / +交互降级 / 不给裁剪 / 缓存 512MB / 上限给足)。

## 构建与运行

```powershell
# 前置:先构建 geobench(本基准默认链接它的 Release 静态库)
cd src\geobench
cmake -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release

# 本基准(Qt 6.8.3 LTS;Qt 路径经 -DCMAKE_PREFIX_PATH 传入)
cd tools\svgscene-bench
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH=D:/Qt/6.8.3/msvc2022_64
cmake --build build --config Release
# 参数: [分块阈值=256] [QPixmapCache 上限 MB=128] [最大设备缓存尺寸=4096] [四实现对比的形状数上限=10000]
# 需要 Qt DLL 在 PATH 上;无显示器环境用 offscreen
$env:PATH = "D:\Qt\6.8.3\msvc2022_64\bin;$env:PATH"
$env:QT_QPA_PLATFORM="offscreen"; .\build\Release\svgscene_bench.exe 256 128 4096 2400
```

`QT_QPA_PLATFORM=offscreen` 必须有;不需要显示器,可在 CI/无桌面环境跑。
第四个参数用于跳过最慢的"旧实现"大形状数行(10000 形状 = 2500 个 item,单帧秒级);
交互口径固定测到 5000 形状。

`geometrize-fast.lib` 的路径是 cache 变量 `GEOMETRIZE_FAST_LIB`,换构建目录/配置时用
`-DGEOMETRIZE_FAST_LIB=...` 覆盖,不必改 CMakeLists(2026-10-07 之前的挂账已修)。

## 关键结论

### F3.9(2026-09-22,512×384 图 / 900×600 视口 / 每批 4 形状)

- 旧实现每帧要合成"形状数/4"层全画布图层,5000 形状时帧耗时 371ms、缓存内存 2.5GB;
  分块实现为 2.6ms / 41MB,10000 形状仍 4.9ms / 82MB。
  绝对数值受机器负载与内存压力影响(旧实现一侧同参数重跑 5000 形状在 371~1000ms 之间),
  看量级与趋势,别当基准分;分块一侧稳定在个位数毫秒。
- **QPixmapCache 上限是隐藏变量**:设备坐标缓存的 item 位图走 Qt 全局缓存,默认 10MB
  只装得下约 5 个全画布图层;超出后逐帧重渲染(5000 形状 68ms/帧)。应用在 `main.cpp`
  把上限提到 128MB。
- 画面等价性:分块实现与旧实现逐像素比,36% 像素差 1 个通道单位、0.03% 差 2(分层合成多一次
  8 位舍入);把阈值放大到不分块时与"单 item"方案逐像素相同——差异只来自分层合成,不是累积逻辑。

### F3.10(2026-10-07,1024×768 画布 / 900×600 视口 / 每批 4 形状 / 分块实现)

`maximumCacheSize` 取值的三档对比(缩放 tick 中位耗时 ms,5000 形状 = 20 块):

| 配置 | 1x | 2x | 4x | 6x | 8x | 16x | 2x 拖动 | 6x 拖动 | 1x 生成 | 6x 生成 |
|---|---|---|---|---|---|---|---|---|---|---|
| 4096(应用现状) | 404 | 1198 | 42 | 42 | 48 | 33 | **680** | 40 | 12 | 49 |
| 给足(32767) | 81 | 267 | 1409 | 2844 | 5284 | **15769** | 0.8 | **1405** | 10 | 1516 |
| 4096 + 交互降级 | 9.5 | 7.0 | 6.6 | 6.8 | 7.0 | 6.4 | 6.8 | 6.0 | 9.4 | 12 |

- **"把 maximumCacheSize 给足"是错的**:Qt 的 DeviceCoordinateCache 会按**整幅设备矩形**
  去建/维护缓存位图,1024 画布 ×16 缩放 = 16384×12288,单 tick 从 33 ms 恶化到 **15769 ms**。
  现有 4096 是保护性的,保留不动(见 ROADMAP 陷阱 #16 的补充)。
- **有效的是"交互期切 item 坐标缓存"**:item 坐标缓存不随视口变换失效,缩放/拖动每 tick
  只做位图缩放合成。5000 形状实测缩放 tick 404→9.5 ms(43x)、1198→7.0 ms(171x)、
  1668→6.3 ms(265x),拖动 729→7.3 ms(100x),生成帧 41→16 ms。
- 代价与边界:
  - 手势起点有一次缓存重建顿挫(5000 形状约 266 ms,1000 形状约 46 ms),之后每 tick 个位数毫秒;
  - 交互期放大时画面是位图放大:**1x 下与常态逐字节相同**(0 像素差),4x 下 94.7% 像素有差、
    单通道最大差 78;停手 0.2 s 恢复清晰(用户已同意交互期降质);
  - 去掉 `ItemClipsToShape` 无收益且**会改变画面**(单通道最大差 184),保留;
  - QPixmapCache 上限 128MB 与 512MB 在 ≤5000 形状下无差别,保留 128MB(应用侧另有按块数的
    自适应抬高兜底,见 `imagetasksvgscene.cpp` 的 `tunePixmapCacheForChunkCount`)。
